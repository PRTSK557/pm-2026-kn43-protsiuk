## 2. Як рахувалася симуляція

| Поле | Значення |
| --- | --- |
| Інструмент | власний скрипт Python, [montecarlo.py](./montecarlo.py) |
| Прогонів | 10 000 |
| Що тягнеться випадково | velocity одного зі спринтів історії, з поверненням |
| Як рахується дата прогнозу | останній день спринта, на якому закінчується робота: для сценарію «весь перший реліз» кінець спринта 1 плюс (P − 1) × 14 днів, для сценарію залишку кінець останнього спринта плюс P × 14 днів |

Ядро скрипта:

```python
def simulate(remaining, velocities, runs=10000, seed=2026):
    rnd = random.Random(seed)          # фіксований seed, щоб прогін повторювався
    results = []
    for _ in range(runs):
        left, sprints = remaining, 0
        while left > 0:                # поки залишок більший за нуль
            left -= rnd.choice(velocities)
            sprints += 1
        results.append(sprints)
    results.sort()
    pct = lambda p: results[math.ceil(p * runs) - 1]
    return pct(0.50), pct(0.85)
```

Перцентиль тут береться як найменше число спринтів, нижче або на рівні якого лежить потрібна частка прогонів. Оскільки спринти цілі, округлення вгору виходить само.

Як повторити:
- на навчальних даних: `python lr09_forecast/montecarlo.py reference`;
- на своїх даних: `python lr09_forecast/montecarlo.py <залишок> <velocity1> <velocity2>`.

Перевірка циклу: прогін із трьома різними seed (1, 7, 42) дав ті самі перцентилі до спринта. Отже, 10 000 прогонів достатньо, і результат не залежить від того, як випали випадкові числа.
